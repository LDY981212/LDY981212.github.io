# 포트폴리오 피드백 반영 설계

날짜: 2026-08-05

## 받은 피드백

1. 전체적으로 내용이 방대하다. 핵심이 따로 보였으면 한다. 면접관은 다 읽지 않는다.
2. 사용자 경험이 중요하다는 개발자인데, 그 문구가 보이는 UI의 CLS를 고려하지 않았다.
3. 개인 프로젝트의 내용이 의미 없다. 무엇을 보라는 것인지, 무엇을 얻는지 모르겠다.
4. 포트폴리오 내용은 전부 하나하나 답할 수 있어야 한다. 덜어낼 것을 더는 걸 추천한다.

네 항목의 공통 요지는 하나다. **분량이 신뢰를 만들지 않는다.** 그래서 더하는 작업(2번의
핵심 노출)과 덜어내는 작업(1·3·4번)을 같이 한다.

## 1. 히어로 CLS 제거

### 측정

정적 빌드(`out/`)를 로컬 서버로 띄우고, 실제 Chrome에 페이지 스크립트보다 먼저
`PerformanceObserver`를 심어 `layout-shift` 엔트리를 누적했다.

| 조건 | 누적 CLS | 시프트 |
| --- | --- | --- |
| 26초 · 1440x900 | 0.01096 | 9건 |
| 26초 · 390x844 | 0.00722 | 9건 |
| **240초 · 1440x900** | **0.11295** | **92건** |

간격이 정확히 2.6초로 `WORD_INTERVAL_MS`와 일치했다. 한 번의 값은 작지만 순환이
무기한 반복되므로 체류 시간에 비례해 계속 쌓이고, 4분이면 Core Web Vitals의 "good"
기준 0.1을 넘긴다. 면접관이 포트폴리오를 읽는 시간이면 도달하는 값이다.

### 원인

두 가지가 겹쳐 있었다.

- `AnimatePresence mode="wait"` — 이전 단어가 사라진 뒤에야 새 단어가 들어와서, 그
  사이 슬롯이 조사(`을`/`를`)만 남는 폭으로 붕괴한다. 뒤의 `깊이 고민하고,`가 왼쪽으로
  튀었다 돌아온다.
- `Marker`의 `layout` prop — 폭 변화를 애니메이션으로 처리해, 그동안 매 프레임 리플로우가
  난다.

### 결정

가장 긴 단어 기준으로 폭을 예약하는 방법(inline-grid에 전 단어를 겹쳐 두고 비활성은
`visibility: hidden`)도 검토했다. 시프트는 사라지지만 짧은 단어(`성능`)가 뜰 때 빈 여백이
남고, 회전이 문장에 더해주는 정보가 없다. 그래서 **문구를 `사용자 경험을`로 고정**한다.
리뷰어가 문제 삼은 바로 그 문구를 남기되, 아래 HIGHLIGHTS가 근거로 받친다.

형광펜은 `backgroundSize`만 움직여 레이아웃에 영향이 없으므로 유지한다.

### 검증

`scripts/measure-cls.mjs`(`npm run cls`)로 남긴다. CLS가 0.1을 넘으면 종료 코드 1을
돌려준다. 헤드리스로 도는 이유는, 백그라운드 탭에서는 `requestAnimationFrame`이 멈춰
애니메이션이 진행되지 않고 렌더가 없으니 `layout-shift` 엔트리도 나오지 않기 때문이다.

**결과: 4분 체류 CLS 0.11295 → 0, 92건 → 0건. 모바일(390px)도 0.**

## 2. HIGHLIGHTS 섹션 신설

가장 강한 재료가 모달 3단계 깊이에 묻혀 있었다. 측정된 수치 셋만 히어로 바로 아래로
꺼내고, 각 카드에서 근거가 있는 모달로 바로 들어가게 한다.

| 수치 | 내용 | 출처 |
| --- | --- | --- |
| 25건 | 동시 처리 한계. 병목을 메모리 압박으로 실측 확정, 디스크 증설안 폐기 | ClipNow |
| 매초 → 0 | 시청 화면 전체 재렌더 제거 | Player |
| 0.113 → 0 | 이 페이지의 CLS | 개인 포트폴리오 웹 |

원칙: **모달의 트러블슈팅에 근거가 있는 수치만 쓴다.** 카드를 누르면 그 근거가 열리므로
요약과 원본이 어긋나면 바로 들킨다. "최적화", "대폭 개선" 같은 형용사는 넣지 않는다.

섹션 순서도 바꾼다. `히어로 → PROFILES → SKILLS → PROJECTS → CAREER`에서
**`히어로 → HIGHLIGHTS → PROJECTS → CAREER → SKILLS → PROFILES`**로. 생년월일과
연락처를 가장 먼저 읽히게 두면 정작 봐야 할 것이 네 겹 뒤로 밀린다.

## 3. 프로젝트 8건 → 주요 4건 + 아카이브 4건

- **카드 + 모달**: ClipNow, Player, Webinow, 개인 포트폴리오 웹
- **한 줄 아카이브**: FlowIt, Moving, HanCook, View My Startup (제목·요약·기간·GitHub)

`전체 / 회사 / 개인` 필터는 삭제한다. 4장이면 필터가 필요 없고, 기존 라벨은 틀려 있었다.
`COMPANY_ROUTERS`에 없으면 전부 `개인`으로 세어 부트캠프 팀 프로젝트 넷이 개인
프로젝트로 집계됐다(실제 개인 프로젝트는 하나).

데이터는 지우지 않고 `archived: true` 플래그만 단다. `scripts/build-resume-pdf.mjs`가
이 배열의 `solution`을 **인덱스로** 참조하기 때문에, 항목을 지우면 이력서 PDF가 조용히
다른 내용을 싣는다. 웹에서 덜어내는 것과 이력서에서 지우는 것은 별개의 결정이다.

## 4. 개인 프로젝트에 답할 거리 만들기

"이 개인 프로젝트에서 무엇을 얻는가"에 대한 답으로, 이번 CLS 작업 자체를 트러블슈팅
항목으로 넣는다. 원인 두 가지, 측정 방법, before/after 수치, 검토했다가 버린 대안까지
적는다. 기존 항목(FOUC 제거, Tailwind v4 `dark:` 변형, 모션 줄이기)은 유지한다.

## 5. 답할 수 없는 항목 삭제

| 대상 | 이유 |
| --- | --- |
| HanCook · refreshToken 재발급 | 본문에 "정확한 원인은 파악하지 못했으나" |
| Moving · Jest SVG 모킹 | 본문에 "svg 모킹은 실패했지만" |
| View My Startup · 드롭다운 | 해결이 "prop을 넘겨주었습니다"라 트러블슈팅이 아님 |
| Moving · `{ name: "Jest", detail: "" }` | 빈 값이 그대로 배포 중 |
| 개인 포트폴리오 웹 · Framer Motion 설명 | 제거한 "강조어 순환"을 계속 광고 |

## 6. 중복 제거

`"8건 · 2024–2026"`이 `sections.ts`와 `Project.tsx` 두 곳에 하드코딩돼 한쪽만 고치면
어긋났다. `SectionHeading`이 `id`만 받아 `sections.ts`에서 제목과 eyebrow를 읽도록
바꾸고, 건수는 `featuredItems.length`로 계산한다.

`build-pdf.mjs`도 같은 플래그를 읽어 사이트와 같은 구성으로 출력한다. 화면과 인쇄물이
다른 이야기를 하면 안 된다.

## 건드리지 않은 것

- `build-resume-pdf.mjs`의 `careerHighlights` · `sideProjects` — 이력서는 이미 손으로
  큐레이션돼 있고, 웹의 아카이브 결정과는 별개다.
- 아카이브로 내린 프로젝트의 `stack.detail` 복붙 문구 — 사이트·PDF 어디에도 렌더되지
  않아 지금은 보이지 않는다. 다시 꺼낼 때 정리할 항목으로 남긴다.

## 부록 · 배포 후에 드러난 것 (2026-08-06)

로컬 정적 서버에서 0을 확인하고 배포한 뒤, 같은 스크립트를 배포된 주소로 돌리자
첫 방문 CLS 0.034 · 643ms 지점의 시프트 1건이 남아 있었다. 조건을 갈라 확인했다.

| 조건 | CLS |
| --- | --- |
| 콜드 로드 | 0.03375 · 1건 |
| 폰트 요청 차단 | 0 |
| 웜 캐시 (2회차) | 0 |

`PretendardVariable.woff2`가 2MB인데 `display: swap`이라, 폴백으로 먼저 그린 뒤
교체하는 순간 글자 폭이 바뀌어 히어로와 내비게이션이 함께 밀렸다. 회전 단어와 무관하게
원래 있던 문제이고, 로컬에서는 폰트가 즉시 도착해 드러나지 않았다.

세 가지를 순서대로 걸었다.

1. **서브셋** — 한글 음절 전체 범위(U+AC00–D7A3)를 넣는 안은 1.7MB라 실측 후 버렸다.
   실제 쓰는 글자만 남기면 177KB. 목록이 낡지 않도록 `src/`를 훑어 글자를 모으는
   `scripts/build-font-subset.mjs`를 `prebuild`에 걸었다.
2. **`display: "optional"`** — `swap`은 늦게 도착해도 반드시 교체하므로 시프트가 남는다.
   `optional`은 짧은 차단 구간을 넘기면 그 방문에 교체하지 않아 시프트 경로 자체가 없다.
3. **`adjustFontFallback: false`** — 1·2를 걸고도 느린 회선 + CPU 4배 스로틀에서는
   시프트가 그대로 재현됐다. 배포된 CSS를 열어보니 프레임워크가 폴백을 `local("Arial")`에
   Arial 기준 지표 보정으로 만들고 있었다. Arial에는 한글 글리프가 없어 실제로는 시스템
   한글 폰트가 쓰이는데 보정값이 그 폰트와 맞지 않아, 교체 시 오히려 더 크게 밀렸다.
   끄자 같은 조건에서 **0.034 → 0.0005**.

### 라이브 실측 (배포된 주소)

| 조건 | CLS |
| --- | --- |
| 콜드 · 데스크톱 1440 | **0** |
| 콜드 · 모바일 390 | **0** |
| 4분 체류 | **0** |
| Fast 3G + CPU 4x 스로틀 | 0.00058 |

폰트는 2,009KB → 177KB. 페이지와 모달 4개에 렌더되는 고유 문자 649자 전부를 서브셋이
커버하는지 `document.fonts.check`로 확인했다.

**교훈은 절차에 남긴다.** 로컬에서 0이 나왔다고 끝냈으면 못 찾았다. `npm run cls`는
`CLS_URL` 환경변수로 배포된 주소를 잴 수 있고, 배포 후 한 번 더 재는 것을 기본으로 한다.
